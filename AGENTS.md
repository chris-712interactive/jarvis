# AGENTS.md

## Cursor Cloud specific instructions

Jarvis is a monorepo. The only implemented service is the web app at **`apps/web`** — a Next.js 16 (App Router, Turbopack) + React 19 command center with Phase 2 chat + Phase 3 async jobs. All commands below run from `apps/web`. Standard run/build/lint/seed commands are documented in the root `README.md` and `apps/web/package.json` (`dev`, `build`, `start`, `lint`, `db:seed`); prefer those.

### Non-obvious notes

- **Storage is local SQLite via Drizzle + Node’s built-in `node:sqlite`** (Node 22+), not Postgres and not `better-sqlite3`. `apps/web/lib/db/index.ts` auto-creates the DB file and tables on first access (including `jobs.brief` + `notifications`), and the schema is seeded automatically on the first request — so `npm run dev` alone is enough; `npm run db:seed` is optional. DB lives at `apps/web/data/jarvis.db` (git-ignored, WAL mode). Delete the `apps/web/data/` directory to reset to a fresh seed. Override the location with `JARVIS_DB_PATH` (see `apps/web/.env.example`); no env vars are required to run the hub UI alone.
- **Phase 2 chat** needs `OPENAI_API_KEY` in `apps/web/.env.local`. Model split: `OPENAI_MODEL` (default `gpt-4o-mini`) for uplink chat, briefing polish, email intent, and short message drafts; `OPENAI_PLANNING_MODEL` (default `gpt-4o`, falls back to `OPENAI_MODEL`) for research/ops vault notes, recommendation polish, and weekly reviews/memory. Without the key, `/api/chat` returns 503 and the uplink panel shows setup instructions. Streaming + tools live in `app/api/chat/route.ts` with tools in `lib/chat/tools.ts`. If the uplink shows an error, it should now include the real OpenAI/setup message (invalid key, unknown model, quota, etc.). Lane routing: if the user names a lane (“ForgeRep”, …), tools accept `lane` and resolve via `lib/chat/resolve-lane.ts` — the uplink dropdown is only a soft fallback and defaults to **All lanes**.
- **Phase 3 async jobs**: chat can call `start_job` / `get_job` / `resolve_job` / `clear_needs_you` / `write_vault_note` / `draft_daily_post`. Jobs move `queued → running → done|needs_you` via `lib/jobs/runner.ts`. Kick with `POST /api/jobs/process` (also auto-kicked on job create and by `JobPoller` on the dashboard; chat emits `jarvis:jobs-changed` after job tools). Research/ops jobs **write a markdown note** into the lane vault under `Jarvis Jobs/` (planning model when keyed; otherwise a stub note). **Message jobs** write channel/Skool drafts under `Content/<channel>/` (chat model) and finish as **needs_you** (approve-before-post). **Code jobs** launch Cursor Cloud Agents via `lib/cursor/agents.ts` when `CURSOR_API_KEY` is set and the lane has a GitHub `repoUrl` (repo must be connected under Cursor Integrations). Agent id/run id are stored on the job; the poller refreshes until the run finishes and surfaces the agent/PR URL. Completions write rows to `notifications` (header **Alerts** panel; `GET/PATCH /api/notifications`). Vault writes also via `POST /api/projects/[id]/notes/write`. **Needs you** items are hub DB records (job status or project `needsYou`) — not Obsidian notes. Clear them with **Approve/Resolve** on the Priority list, or ask the uplink to resolve them.
- **Trust budgets**: each lane has `trustLevel` (`observer` → `drafter` → `operator` → `autopilot`, default `operator`). Policy in `lib/trust/policy.ts`. Observer is read-only; drafter can draft but not send email / auto-open PRs; operator is the approve gate; autopilot narrow-finishes safe non-email code successes. Edit on the project form. Chat prompt lists each lane’s trust.
- **Daily content**: lanes can set `contentChannel` (e.g. `skool`), `contentBrief`, and `dailyContent`. Cron: `GET/POST /api/cron/daily-content` or unified `GET/POST /api/cron/tick` (Bearer `CRON_SECRET` in production). Seed includes **Carline Dad Codes** with daily Skool drafting enabled.
- **Cron tick + briefings + weekly reviews + PR CI + deploy health**: Prefer `/api/cron/tick` every 5–15 min on a persistent host (see `docs/DEPLOY.md`). It runs jobs, email ingest, daily content, morning/evening briefings (`BRIEFING_TZ` / `BRIEFING_MORNING_HOUR` / `BRIEFING_EVENING_HOUR`), weekly reviews + memory compaction (`WEEKLY_REVIEW_WEEKDAY` / `WEEKLY_REVIEW_HOUR`, default Mon 09:00), a light PR CI watchdog, and production deploy/health probes. Chat tools: `get_briefing`, `run_briefing`, `get_weekly_review`, `run_weekly_review`, `check_pr_ci`, `get_lane_deploy`, `check_deploy_health`. Also `/api/cron/briefing` and `/api/cron/weekly-review`.
- **Weekly memory**: `lib/briefing/weekly-review.ts` writes hub + per-lane notes under `Jarvis Jobs/reviews/{weekKey}…` and overwrites compacted `Memory/<slug>/Current.md` on each vaulted lane so chat can ground on durable memory instead of raw history.
- **GA4 analytics**: optional `gaPropertyId` per lane + `GA4_SERVICE_ACCOUNT_JSON` / `GOOGLE_APPLICATION_CREDENTIALS`. Chat tool `get_lane_analytics`; HTTP `GET /api/projects/[id]/analytics?days=7`. Service account needs Analytics Data API + Viewer on the property.
- **Search Console SEO**: optional `gscSiteUrl` per lane (`sc-domain:example.com` or `https://example.com/`). Chat tool `get_lane_search`; HTTP `GET /api/projects/[id]/search-console?days=28` (sitemaps + URL Inspection by default; `coverage=0` to skip; `inspectUrl=` / `inspectOnly=1`). Reuses the same service account — enable Search Console API and add the SA email as a user (Owner for URL Inspection).
- **Lane recommendations**: `get_lane_recommendations` / `GET /api/projects/[id]/recommendations` joins GA4 + GSC + lane goal/contentBrief into a detailed prioritized plan (site + social ideas). Optional `writeVault=1` → `Jarvis Jobs/recommendations/`. Social advice is demand-proxy only (no native Skool analytics yet).
- **Production deploy health**: optional `productionUrl` + `deployHost` (`url`|`vercel`|`railway`|`aws`) + `deployProjectId`. Cached `deployStatus` on the lane; live via `get_lane_deploy` / `GET /api/projects/[id]/deploy?refresh=1`. Hub strip: `GET /api/deploy/overview`. Webhooks: `POST /api/webhooks/vercel` (`VERCEL_WEBHOOK_SECRET`) and `POST /api/webhooks/railway?secret=` (`DEPLOY_WEBHOOK_SECRET` or `CRON_SECRET`). Needs `VERCEL_TOKEN` / `RAILWAY_TOKEN` for platform API probes. AWS is URL-health in v1.
- **Gmail → code/questions**: OAuth via `GMAIL_CLIENT_ID` / `GMAIL_CLIENT_SECRET` / `GMAIL_REFRESH_TOKEN` (`/api/gmail/oauth/start` once). Per-lane `emailSenders` allowlist. Cron `GET/POST /api/cron/email-ingest` or chat `ingest_emails` classifies each message (`lib/jobs/email-intent.ts`): **code** → Cloud Agent job; **question** → draft reply in Needs you; **ambiguous** → triage Needs you. **Approve & reply** (`resolveJobWithSideEffects`) emails the sender when a draft/completion body exists. Messages get a `Jarvis/Processed` Gmail label.
- **Push-to-talk** uses the browser Web Speech API (Chrome/Edge). Tap **Mic**, speak, tap **Stop** to send.
- **Speak replies** defaults on in the uplink (**Speak on**). Prefers **OpenAI TTS** via `POST /api/speak` (same `OPENAI_API_KEY`; optional `OPENAI_TTS_MODEL` / `OPENAI_TTS_VOICE`, defaults `tts-1` / `onyx`). Falls back to browser `speechSynthesis` if the key is missing or TTS fails. Toggle off to mute. Preference saved in `localStorage`. Click **Test voice** once to unlock audio playback.
- **Ambient wake word** (always-on) is a toggle in the uplink. Default wake phrase is `jarvis` (also accepts “hey/ok/okay/hi jarvis”); editable and saved in `localStorage`. While Ambient is on, the mic watches continuously, pauses during model replies and TTS, and auto-opens the uplink when the wake word is heard. Only a **leading** wake word starts capture; after that, later “Jarvis” in the sentence is kept (so answers like lane names / “Jarvis Jobs” aren’t stripped). Voice-originated answers are spoken back (OpenAI TTS when configured). Requires `OPENAI_API_KEY` — without it wake capture can work but there will be no reply. Best in Chrome/Edge with the tab focused. Ambient capture keeps finals separate from interim hypotheses (no append-on-stutter) and runs `sanitizeVoiceCommand` / `collapseSpeechRepeats` before send so Chrome STT loops like “for Forge for Forge…” get collapsed.
- **Obsidian / markdown vaults** are optional per-project memory. Set `vaultPath` on a project (absolute, `~/...`, or relative to `apps/web`). Read helpers live in `apps/web/lib/vault/notes.ts`; writes via `writeVaultNote` / `write_vault_note` tool / `POST .../notes/write`. Paths are sandboxed to the vault root; `.obsidian` is skipped. Sample vault: `apps/web/fixtures/sample-vault`. **If a lane has no vault path, async jobs that need Obsidian will land in Needs you asking you to configure one.**
- **GitHub reads** use the public API (`lib/github/repo.ts`). Optional `GITHUB_TOKEN` in `.env.local` for private repos / rate limits. Chat tools: `get_repo_summary`, `list_open_prs`. HTTP: `GET /api/projects/[id]/github` (`?view=prs` for pull requests).
- **Cursor Cloud Agents** need `CURSOR_API_KEY` in `apps/web/.env.local` (Dashboard → API Keys). Optional: `CURSOR_AGENT_MODEL`, `CURSOR_AGENT_MODE` (`agent`|`plan`), `CURSOR_AGENT_AUTO_PR` (default true), `CURSOR_AGENT_STARTING_REF`. Without the key (or without a GitHub repo URL on the lane), code jobs land in **Needs you** with setup instructions.
- Deploy notes: `docs/DEPLOY.md`. **Railway**: use the root `Dockerfile` / `railway.toml` (Node 22 image, no native sqlite addon). Attach a volume at `/data` and set `JARVIS_DB_PATH=/data/jarvis.db`. **Vercel serverless is not supported** with on-disk SQLite.
- Dev server runs on `http://localhost:3000`. REST APIs live under `/api/projects`, `/api/projects/[id]`, `/api/projects/[id]/notes`, `/api/projects/[id]/notes/write`, `/api/projects/[id]/github`, `/api/projects/[id]/analytics`, `/api/projects/[id]/search-console`, `/api/projects/[id]/recommendations`, `/api/projects/[id]/deploy`, `/api/deploy/overview`, `/api/webhooks/vercel`, `/api/webhooks/railway`, `/api/cron/tick`, `/api/cron/briefing`, `/api/cron/weekly-review`, `/api/cron/daily-content`, `/api/cron/email-ingest`, `/api/gmail/oauth/start`, `/api/gmail/oauth/callback`, `/api/chat`, `/api/conversations`, `/api/jobs`, `/api/jobs/process`, `/api/speak`, and `/api/notifications`.
- There is no automated test suite yet.

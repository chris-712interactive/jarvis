# AGENTS.md

## Cursor Cloud specific instructions

Jarvis is a monorepo. The only implemented service is the web app at **`apps/web`** — a Next.js 16 (App Router, Turbopack) + React 19 command center with Phase 2 chat + Phase 3 async jobs. All commands below run from `apps/web`. Standard run/build/lint/seed commands are documented in the root `README.md` and `apps/web/package.json` (`dev`, `build`, `start`, `lint`, `db:seed`); prefer those.

### Non-obvious notes

- **Storage is local SQLite via Drizzle**, not Postgres (despite the architecture doc's later-phase suggestion). `apps/web/lib/db/index.ts` auto-creates the DB file and tables on first access (including `jobs.brief` + `notifications`), and the schema is seeded automatically on the first request — so `npm run dev` alone is enough; `npm run db:seed` is optional. DB lives at `apps/web/data/jarvis.db` (git-ignored, WAL mode). Delete the `apps/web/data/` directory to reset to a fresh seed. Override the location with `JARVIS_DB_PATH` (see `apps/web/.env.example`); no env vars are required to run the hub UI alone.
- **Phase 2 chat** needs `OPENAI_API_KEY` in `apps/web/.env.local` (optional `OPENAI_MODEL`, default `gpt-4o-mini`). Without it, `/api/chat` returns 503 and the uplink panel shows setup instructions. Streaming + tools live in `app/api/chat/route.ts` with tools in `lib/chat/tools.ts`. If the uplink shows an error, it should now include the real OpenAI/setup message (invalid key, unknown model, quota, etc.). Lane routing: if the user names a lane (“ForgeRep”, …), tools accept `lane` and resolve via `lib/chat/resolve-lane.ts` — the uplink dropdown is only a soft fallback and defaults to **All lanes**.
- **Phase 3 async jobs**: chat can call `start_job` / `get_job` / `resolve_job` / `clear_needs_you` / `write_vault_note`. Jobs move `queued → running → done|needs_you` via `lib/jobs/runner.ts`. Kick with `POST /api/jobs/process` (also auto-kicked on job create and by `JobPoller` on the dashboard; chat emits `jarvis:jobs-changed` after job tools). Research/ops/message jobs **write a markdown note** into the lane vault under `Jarvis Jobs/` (drafted with OpenAI when `OPENAI_API_KEY` is set; otherwise a stub note). Code → `needs_you` until coding agents exist. Completions write rows to `notifications` (header **Alerts** panel; `GET/PATCH /api/notifications`). Vault writes also via `POST /api/projects/[id]/notes/write`. **Needs you** items are hub DB records (job status or project `needsYou`) — not Obsidian notes. Clear them with **Approve/Resolve** on the Priority list, or ask the uplink to resolve them.
- **Push-to-talk** uses the browser Web Speech API (Chrome/Edge). Tap **Mic**, speak, tap **Stop** to send.
- **Speak replies** defaults on in the uplink (**Speak on**). Every assistant reply is read aloud via browser speech synthesis (typed or voice). Toggle off to mute. Preference saved in `localStorage`.
- **Ambient wake word** (always-on) is a toggle in the uplink. Default wake phrase is `jarvis` (also accepts “hey/ok/okay/hi jarvis”); editable and saved in `localStorage`. While Ambient is on, the mic watches continuously, pauses during model replies and TTS, and auto-opens the uplink when the wake word is heard. Only a **leading** wake word starts capture; after that, later “Jarvis” in the sentence is kept (so answers like lane names / “Jarvis Jobs” aren’t stripped). Voice-originated answers are spoken back with browser speech synthesis. Requires `OPENAI_API_KEY` — without it wake capture can work but there will be no reply. Best in Chrome/Edge with the tab focused. Ambient capture keeps finals separate from interim hypotheses (no append-on-stutter) and runs `sanitizeVoiceCommand` / `collapseSpeechRepeats` before send so Chrome STT loops like “for Forge for Forge…” get collapsed.
- **Obsidian / markdown vaults** are optional per-project memory. Set `vaultPath` on a project (absolute, `~/...`, or relative to `apps/web`). Read helpers live in `apps/web/lib/vault/notes.ts`; writes via `writeVaultNote` / `write_vault_note` tool / `POST .../notes/write`. Paths are sandboxed to the vault root; `.obsidian` is skipped. Sample vault: `apps/web/fixtures/sample-vault`. **If a lane has no vault path, async jobs that need Obsidian will land in Needs you asking you to configure one.**
- `better-sqlite3` is a **native module** compiled during `npm install`. If the dashboard 500s with a "was compiled against a different Node.js version" (NODE_MODULE_VERSION) error after a Node upgrade, run `npm rebuild better-sqlite3` (or reinstall) in `apps/web`.
- Dev server runs on `http://localhost:3000`. REST APIs live under `/api/projects`, `/api/projects/[id]`, `/api/projects/[id]/notes`, `/api/projects/[id]/notes/write`, `/api/chat`, `/api/conversations`, `/api/jobs`, `/api/jobs/process`, and `/api/notifications`.
- There is no automated test suite yet.
